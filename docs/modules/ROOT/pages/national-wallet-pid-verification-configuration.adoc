= National Wallet PID Verification Configuration

This page describes how to configure Keycloak OpenID4VP authentication for presentation flows involving a national wallet PID credential.

The configuration supports both:

* a single-credential login profile;
* a multi-credential login profile where one credential is used for Keycloak user binding and one or more additional credentials are verified as supporting credentials.

== Overview

For the national wallet PID flow, Keycloak acts as an OpenID4VP verifier.

The recommended authentication model is:

. A primary credential identifies the Keycloak user.
. A PID credential is requested as a supporting credential.
. Each credential is verified according to its own format and trust policy.
. Authentication succeeds only when all required credentials are valid.

The PID can be represented as an mDoc credential with:

[source,text]
----
Format: mso_mdoc
Doctype: eu.europa.ec.eudi.pid.1
----

== Prerequisites

* Keycloak with this plugin deployed.
* A public HTTPS Keycloak base URL reachable by the wallet.
* Access to the German EUDI Ecosystem Sandbox Registrar.
* Verifier access and registration certificate material from the Sandbox.
* A wallet containing the credentials required by the selected authentication profile.

== Verifier Certificate Material

The national wallet profile requires verifier certificate material issued or accepted by the German EUDI Sandbox.

[cols="1,2"]
|===
|Field |Description

|Access certificate
|Base64 DER encoded X.509 verifier access certificate.

|Registration certificate
|Full verifier registration certificate JWT.
|===

The access certificate must correspond to the Keycloak signing key used for OpenID4VP request objects and must identify the public hostname used by Keycloak.

The registration certificate should describe the verifier purpose and the credential claims requested from the wallet.

For a PID mDoc profile, the registration certificate should cover:

[source,text]
----
Format: mso_mdoc
Doctype: eu.europa.ec.eudi.pid.1
Claims:
  eu.europa.ec.eudi.pid.1 / given_name
  eu.europa.ec.eudi.pid.1 / family_name
----

== Keycloak Signing Key

Configure an active realm key provider for signing OpenID4VP request objects.

Recommended key provider properties:

[source,text]
----
Algorithm: ES256
Keystore Type: PKCS12
Key use: sig
----

The private key in this provider must match the public key represented by the configured access certificate.

== OpenID4VP Authenticator Configuration

Open the OpenID4VP authenticator configuration in the Keycloak authentication flow and configure the verifier settings.

Recommended values for national wallet PID verification:

[source,text]
----
Client Identifier Prefix: x509_san_dns
Response mode: direct_post.jwt
Request URI method: get
Custom URL scheme: openid4vp://
Access certificate: <base64 DER access certificate>
Registration certificate: <registration certificate JWT>
Require cryptographic holder binding: On
Maximum age of presented holder-binding proof: 60
Require Not Before claim (SD-JWT): Off
Require Expiration claim (SD-JWT): Off
Verify issuer claim (SD-JWT): On
Fall back to ISO-spec session transcript (mDoc): Off
Reject revoked credentials: Configure according to the deployment's status-list policy
----

Use `direct_post.jwt` when the wallet returns an encrypted authorization response.

The login theme must also support OpenID4VP login buttons. For this plugin, use the `keycloak.v2+oid4vp` login theme.

== Trust Policy Configuration

PID issuer trust is configured per credential requirement.

For the German EUDI Sandbox PID trust list, use:

[source,json]
----
{
  "type": "eudi_pid_trust_list",
  "trustListUrl": "https://bmi.usercontent.opencode.de/eudi-wallet/test-trust-lists/pid-provider.jwt",
  "trustListSigningCertificate": "<base64 DER trust-list signing certificate>",
  "serviceType": "http://uri.etsi.org/19602/SvcType/PID/Issuance"
}
----

The trust-list signing certificate anchors validation of the trust list JWT. The `serviceType` selects the trusted service entries that are valid for PID issuance.

== Multi-Credential PID Profile

Use a multi-credential profile when PID verification should strengthen a login that is still bound to a Keycloak user through a primary credential.

In this model:

* `main` is the primary credential used for Keycloak user recovery;
* `pid` is a supporting credential verified through the EUDI PID trust policy.

[source,json]
----
[
  {
    "id": "dual-national-pid-mdoc",
    "description": "Login with Keycloak credential plus national wallet PID",
    "displayCta": {
      "en": "Login with national PID"
    },
    "credentials": [
      {
        "id": "main",
        "role": "primary",
        "format": "dc+sd-jwt",
        "credentialTypes": [
          "https://credentials.example.com/identity_credential"
        ],
        "claims": [
          "sub",
          "username"
        ],
        "trust": [
          {
            "type": "self"
          }
        ]
      },
      {
        "id": "pid",
        "role": "supporting",
        "format": "mso_mdoc",
        "credentialTypes": [
          "eu.europa.ec.eudi.pid.1"
        ],
        "claims": [
          "eu.europa.ec.eudi.pid.1/given_name",
          "eu.europa.ec.eudi.pid.1/family_name"
        ],
        "trust": [
          {
            "type": "eudi_pid_trust_list",
            "trustListUrl": "https://bmi.usercontent.opencode.de/eudi-wallet/test-trust-lists/pid-provider.jwt",
            "trustListSigningCertificate": "<base64 DER trust-list signing certificate>",
            "serviceType": "http://uri.etsi.org/19602/SvcType/PID/Issuance"
          }
        ]
      }
    ]
  }
]
----

== Single Credential Profile

Use a single-credential profile when only one credential is required for login.

For a Keycloak-issued Identity Credential:

[source,json]
----
[
  {
    "id": "single-identity-login",
    "description": "Login with Keycloak Identity Credential",
    "displayCta": {
      "en": "Sign in with wallet"
    },
    "credentials": [
      {
        "id": "main",
        "role": "primary",
        "format": "dc+sd-jwt",
        "credentialTypes": [
          "https://credentials.example.com/identity_credential"
        ],
        "claims": [
          "sub",
          "username"
        ],
        "trust": [
          {
            "type": "self"
          }
        ]
      }
    ]
  }
]
----

A PID-only profile can also be configured if the PID credential contains the claims required by the deployment's user-binding policy.

== Wallet And Relying Party Requirements

The wallet must contain all credentials required by the selected profile.

The relying-party application can be any OIDC client configured against the Keycloak realm. It only needs to initiate the normal OIDC login flow; the OpenID4VP authentication step is handled by Keycloak.

== Authentication Flow

At runtime:

. The user starts an OIDC login.
. Keycloak displays the wallet login button configured by the selected authentication profile.
. Keycloak creates a signed OpenID4VP authorization request.
. The wallet presents the required credential set.
. Keycloak verifies each credential according to its configured format, claims, holder binding, and trust policy.
. Keycloak binds the authenticated session to the user recovered from the primary credential.
. The OIDC login completes.
